# RL training environment -- versions verified together
#
# ============ Verified combination ============
#   torch        2.5.1+cu124   (from the base image)
#   transformers 4.57.6        <- must stay below 5
#   trl          0.19.1        <- must stay at or below 0.19.1
#   peft / datasets            latest is fine
#
# ============ Why these two upper bounds ============
#   1. trl >= 0.20 imports torch.distributed.fsdp.FSDPModule, which only exists in
#      torch >= 2.6. With torch 2.5.1 this raises ImportError.
#   2. transformers >= 5.0 changed the return type of _is_package_available() from
#      bool to a tuple (False, None). TRL's `if is_vllm_available():` then evaluates a
#      non-empty tuple as truthy, so it tries to import vllm even when vllm is not
#      installed, raising ModuleNotFoundError.
#   Common root cause: the upstream packages declare only lower bounds
#   (e.g. transformers>=4.51), so pip installs an API-incompatible major version.
#
# ============ Install ============
#   pip install "transformers<5" "trl==0.19.1" datasets peft
#
# ============ Evaluation environment (separate, not needed for training) ============
#   vLLM is installed in its own virtualenv with its own torch, because it requires a
#   newer torch than the training image provides. Keep the two apart.
#
#   Two consequences worth knowing:
#     - That environment does NOT have peft, so a LoRA adapter must be merged into a
#       full model in the training environment first (see src/merge_adapter.py).
#     - Evaluation is ~12x faster than with HF generate: about 3 minutes for 1,319
#       problems versus 30-36 minutes.
#
#   If flashinfer fails to JIT-compile against the system CUDA toolkit, set
#   VLLM_USE_FLASHINFER_SAMPLER=0 (see docs/PITFALLS.md).

transformers<5
trl==0.19.1
datasets
peft
