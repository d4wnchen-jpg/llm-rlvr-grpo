## 1. 结果（★ 协议已修正，这是唯一可引用的一组数字）

**协议**：GSM8K test（1319 题，held-out），vLLM 贪心，`max_new_tokens=512`，
**显式** `repetition_penalty=1.0` + `eos_token_id=[151645,151643]`，同一批题（指纹校验）。

| 模型（Qwen2.5-1.5B-Instruct + LoRA r32） | 正确 | 准确率 | Δ | McNemar p |
|---|---|---|---|---|
| 基座 | 966/1319 | **73.2%** | — | — |
| + GRPO，600 步 | 988/1319 | 74.9% | +1.7 | 0.092 ❌ |
| + GRPO，1000 步 | 998/1319 | 75.7% | +2.4 | **0.017** ✅ |
| **+ GRPO，1500 步** | **1016/1319** | **77.0%** | **+3.8** | **0.0003** ✅✅ |
| + SFT（同规模对照） | — | _待补_ | | |

**曲线单调、未饱和**（最后 500 步斜率 = 最初 600 步斜率）：

```
0 →  600 步：+1.7 点  (0.0028 点/步)
600 → 1000 步：+0.7 点  (0.0018 点/步)
1000 → 1500 步：+1.4 点  (0.0028 点/步)   ← 还在涨
```

**基座 73.2% 与 Qwen2.5 论文的 73.2%（4-shot）吻合** → 协议正确性的旁证。

### 训练配置（run2，产出上述 1500 步的模型）

```
--steps 1500 --num-generations 8 --batch-size 8 --grad-accum 2
--max-completion-length 512 --lr 5e-6
--lr-scheduler-type constant_with_warmup --warmup-ratio 0.03
--beta 0.005 --use-lora --lora-r 32 --no-vllm
```
耗时 **11 h 08 min**（26.7 s/it）≈ **11 GPU·h ≈ ¥22**

### 与公开结果的对照

[RLVR-vs-SFT-Qwen2.5-1.5b](https://github.com/jayminbhan/RLVR-vs-SFT-Qwen2.5-1.5b)：
同模型同数据，verl + vLLM + 6×4090（**193 GPU·h**），GRPO **+11.9**、SFT **−15.2**。

| | 他们 | 我们 |
|---|---|---|
| 每优化步增益 | 0.0031 点/步 | **0.0025 点/步**（接近）|
| 每步 prompt 数 | ~25 | **2** |
| 每 prompt 数据效率 | 高 ~12× | 低 |

→ 本项目的三个观察角度：**① 单卡条件下的算力—收益比 ② 为什么朴素配置一步都不动 ③ 训练数据的难度分布**。

## 1.5 发现（都在同一批 1319 题上测出，不是训练出来的）

### A. 一个静默默认参数决定结论是否显著

同引擎（HF）、同批题、**只改 `repetition_penalty`**：

| 协议 | 基座 | +GRPO 1500 | Δ | p | 结论 |
|---|---|---|---|---|---|
| `rp=1.1`（HF 静默默认）| 949 | 967 | +1.4 | **0.26** | ❌ 无提升 |
| **`rp=1.0`（显式）** | 963 | 1007 | **+3.3** | **0.0021** | ✅✅ 极显著 |
| `rp=1.0`（vLLM 默认）| 966 | 1016 | +3.8 | 0.0003 | ✅✅ |

逐题分解（rp 1.1→1.0）：基座 131 修好 / 117 弄坏（净 +14）；RL 130 / **90**（净 **+40**）。
→ **约 250 题（19%）被翻转，净效果只有 +14/+40** → **解码参数的翻转噪声与真实效应同量级**。

**机制**：基座更重复（4-gram 重复率 0.111 vs RL 0.081）→ 重复惩罚对它破坏更大（117 vs 90）✓

### B. RL 学到的是「更不重复」，不是「更长」

| | 平均长度 | 词汇多样性 | 4-gram 重复率 | 自我纠错标记 |
|---|---|---|---|---|
| 基座 | 994 | 0.445 | 0.111 | 15（0.7%）|
| +GRPO 1500 | **927（−6.7%）** | **0.478（+7.3%）** | **0.081（−27%）** | 11（0.6%）|

**CoT 反而变短**（与 R1-Zero 的"长度增长"相反）；重复度降 27%；**答错的回答反而更长**（两个模型都是）。

### C. 负结果：没有 aha moment

自我纠错标记 15 → 11，**没有变化**。在 1.5B + LoRA + 1500 步这个规模上，R1-Zero 式的自我纠错**没有出现**。

### D. 收益**部分依赖训练指令**（重要 caveat）

| prompt 模板 | 基座 | RL | Δ | p |
|---|---|---|---|---|
| `default`（训练用的）| 73.2% | 77.0% | **+3.8** | 0.0003 ✅✅ |
| `alt`（同义改写，仍要求 `\boxed{}`）| 73.1% | 77.1% | **+4.0** | 0.0002 ✅✅ |
| **`minimal`（不给指令）** | 70.7% | 72.3% | **+1.6** | **0.17** ❌ |

去掉指令：基座 −2.5 点，**RL −4.7 点** → **RL 更依赖指令** → 收益含「格式适配」成分（与 B 一致）。
空预测率四协议均 0–1/1319（不是提取失败）；但 minimal 下提取靠"最后一个数字"兜底，
「多少来自格式适配 vs 提取噪声」未隔离。

### 两类扰动对比

| 扰动 | 翻转量 | 净效果 | 性质 |
|---|---|---|---|
| 换模板（default→alt）| base 120 / rl 131 题（9–10%）| −2 / +1 | ✅ 对称 → 只是噪声 |
| 贪心 → 采样（T=0.8/top_p=0.95）| 219 题（16.6%）| −15（p=0.34）| ✅ 对称 → 只是噪声 |
| 改 rp（1.1→1.0）| base 248 / rl 220 题（17–19%）| +14 / +40 | ⚠️ **有偏 → 会改结论** |
| 改样本数（G=1 → G=8）| — | +0.53 → **+1.78** | ⚠️ **有偏 → 会改结论** |

**翻转量预测不了结论稳定性，翻转的"偏性"才能。**
换模板翻转 120 题（比真实效应 +50 还多）却对称 → 配对检验仍有效；
贪心↔采样翻转 219 题、净只有 −15 → 结论纹丝不动；
而 rp 和样本数这两类扰动翻转量并不更大，却直接把结论改写。

### E. 测量功效不足会翻转结论（2026-09-14 补测）

同一批 1319 题、同一个合并模型、同一套 vLLM 管线，**只改每题的采样条数**：

| 测法 | 采样口径的 Δ | 当时得出的结论 |
|---|---|---|
| 单条生成/题（G=1）| +0.53（p=0.69）| ❌「增益消失了」 |
| **8 条/题（G=8）** | **+1.78（95% CI [+0.87, +2.70]）** | ✅「减半，但仍显著」 |

贪心口径 **+3.49**（p=0.0009）。交互 = +1.71（95% CI [−0.43, +3.88]）→ **交互不显著**，
所以**不能**说"增益依赖解码口径" —— 同一模型上"这个口径显著、那个口径不显著"推不出交互。

**一个 ~2 点的效应，用 1 条/题去测会得出相反的结论。**
这是发现 A 的同一道理，只是这次的"口径"是**样本数**而不是解码参数。
→ **任何 Δ 都必须带置信区间**；`analyze_paired.py` 就是为此写的。

**顺带这条测量自证了评分管线无偏**：base 在 test 上 G=8 的 `p_mean = 0.7201`，
单条采样评测 `951/1319 = 0.7211` —— 两套独立测量差 **0.1 个点**。

### F. GSM8K 的 train 比 test 容易约 10 点（同管线实测）

| | train（随机 2000）| test（1319）|
|---|---|---|
| p_mean (G=8) | **0.8214** | **0.7201** |
| pass@8 | 96.8% | 92.8% |
| 退化率（k=0 或 k=8）| 57.9% | 50.2% |
| 全对 / 全错 | 1093 / 65 | 567 / 95 |

→ 差距是真的（不是评分脚本有偏），所以**「数据接近饱和」这个结论要限定在 train**。
train 上 57.9% 的 GRPO 组零梯度，其中 **94.4% 是全对**（不是全错）——
浪费来自"题太简单"，而不是"题太难"。

### 被推翻的假设（记录，避免重走）

- ❌「RL 让 CoT 变长 → 被重复惩罚」→ **数据说 CoT 变短了**（994→927）
- ❌「rp 对 RL 伤害更大」→ 实际是「**rp=1.1 对基座破坏更多**（117 vs 90）」，RL 净赚更多是因为"被破坏得少"
- ❌「vLLM 与 HF 引擎差异很大」→ 同参数下只差 0.2–0.7 点（小样本上的 10 点差距全是 rp）

## 2. 评测协议（必须遵守，否则数字全部作废）

| 规则 | 为什么 |
|---|---|
| **显式传 `repetition_penalty`** | HF 的 `generate` **静默继承**模型 `generation_config` 里的值（Qwen2.5 = **1.1**），vLLM 默认 **1.0** → **实测差 10 个点**。HF rp=1.1 给 63/100，rp=1.0 给 74/100，vLLM 给 75/100 |
| **显式传 `eos_token_id` / `stop_token_ids`** | Qwen2.5 有**两个** EOS（151645 `<|im_end|>`、151643 `<|endoftext|>`）；HF 继承两个，vLLM 自推的可能不同 |
| **同一批题 + 同一 `--limit`** | `--limit N` = `rows[:N]`；`compare_results.py` 用子集指纹强制校验 |
| **同一引擎** | 引擎本身只差 ~1 点，但**换引擎后所有被比较的模型都要重跑** |
| 训练 train split / 评测 test split | 天然无污染 |
| 配对检验 | 同一批题 → 用 **McNemar 精确检验**，不用独立两比例检验 |

**显著线**：1319 题、基座 73.2% → **+2.0 点（净翻转 26 题）** ≈ p<0.05。

> ★ **一句话教训**：**凡是要跨实现比较的数值参数，一律显式传。**
> 框架的"合理默认"在特定组合下就是错，而且**不报错**。

**协议修正的因果（比数字重要）**：初版漏传 `repetition_penalty` → HF 用了 1.1 →
所有数字低约 10 点，**并把 Δ 从 +3.8 压缩成 +1.4**（RL 模型 CoT 更长，受重复惩罚伤害更大，
所以旧协议**系统性地掩盖了 RL 的效果**）。

## 3. 为什么第一个实验（150 步）完全不动 —— 五条诊断

它 Δ=−0.5（p=0.61），但**是可解释的负结果**，不是"失败"：

1. **优化太弱（主因）**：`lr=1e-6` 是**全参微调**的量级，我们用的却是 **LoRA**，且 linear 调度衰减归零。
   **硬证据**：训练后 `lora_B |max| = 3.96e-05`，基本停在零初始化（改对后 1.88e-3，**47×**）
2. **KL 锚太死**：`beta=0.04` vs 参考实现 0.001（差 40×）
3. **信号密度低**：`frac_reward_zero_std ≈ 0.5` —— 一半的组零方差、零梯度。
   实测（基座 × train 前 2000 题 × G=8，2026-09-14）：退化 **57.9%**，i.i.d. 零假设
   （二项，p 用实测均值 **0.821**）只有 **20.7%** → **2.8×** → **双峰成立**。
   但退化里 **k=8 全对占 1093 题（94.4%）**，k=0 全错只有 65 题（5.6%）
   → **浪费几乎全来自"题太简单"**，不是"题太难"。⚠️ 旧版这里用贪心通过率 0.72 当零假设，是错的
4. **数据接近饱和**：同批实测平均单条通过率 **0.821**、pass@8 **96.8%**、8 条全错仅 **3.25%**。
   这个模型在 GSM8K 上几乎没有"不会做"的题，只有"一次做不对"的题 →
   GRPO 能推的只有中间 **42.1%** 的带，上升空间本来就小
5. **有效数据量极小**：数据池 7473，1500 步 × 2 prompt = 只采样 **3000 个 prompt（epoch 0.40）**，
   再打五折 → **约 750 道题真的产生梯度**；而且**一个优化步只有 2 道题** → 梯度噪声大
   （证据：改了 232 题只净赚 18 题）

### vLLM 使用的三个必须记得的点

```bash
export VLLM_USE_FLASHINFER_SAMPLER=0     # 否则 flashinfer JIT 与 CUDA 12.4 冲突，引擎起不来
# gpu_memory_utilization=0.75            # 0.85 会因 KV cache 超预算 0.2GiB 而启动失败
# ln -sf /root/venv-vllm/bin/ninja /usr/local/bin/ninja   # 不 activate venv 时 PATH 里没有它
```

**永远不用 `source activate`**——一律用绝对路径，避免把 shell 的 python 搞混：
```
用 base 环境（train / merge / compare）→ python3
用 vLLM 环境（eval / 筛题）           → /root/venv-vllm/bin/python
```

### 五个"静默"坑（都不报错，靠日志/源码才挖出来）

| # | 静默继承了错误的默认值 | 后果 |
|---|---|---|
| 1 | transformers 的 **fp32** 加载 | 白吃 2.9 GiB |

## 5. 下一步

**已完成**：

- ✅ **主结果**：贪心 **+3.49**（p=0.0009）；采样（G=8）**+1.78**（95% CI [+0.87, +2.70]）
- ✅ **评测口径对照**：贪心/采样 2×2 + 交互检验（交互 **不显著**，见 1.5 节 E）
- ✅ **难度筛选**：train 2000 题 × G=8 评分（57.9% 退化，其中 94.4% 是全对）
- ✅ **test 同管线评分**：定位了 train/test 的 10 点差距，并自证评分管线无偏（见 1.5 节 F）

**进行中**：换种子复现（`run_seeds.sh`，两个额外种子，各 1500 步 ≈ 11 h）。
动机：主结果目前只有 1 个种子，而 1.5 节 E 已经证明**测量功效不足会翻转结论** ——
**单个训练 run 是同一风险在训练层面的版本**。

**已决定不做**（记录理由，避免重走）：

| 事项 | 为什么不做 |
|---|---|
| SFT 对照 | 「RL 优于 SFT」在同模型同数据上已有公开结论（参考项目 SFT −15.2），补它信息量低 |
| 筛题后重新训练（run3/run4）| 单种子单臂分不清"筛题有效"和"run 间抖动"；要可解释需 2 种子 × 2 臂 = 4 次跑 |

**训练侧待改进项**（按性价比）：

1. `--grad-accum 8`（每步 8 道题，微批显存不变）→ 攻梯度噪声，**尚无验证**
2. 评测已迁 vLLM（3 分钟/次）；**训练 rollout 仍是 HF generate**，上 vLLM 只快 1.3–2×，
   且 TRL 0.19.1 没有 vLLM↔策略分布的 importance sampling 修正 → 暂不动
3. `use_liger_loss=True`（融合 lm_head+loss，省掉那份 logits）—— 未试

## 6. 关键文件

| 文件 | 作用 |
|---|---|
| `train_grpo.py` | 训练主脚本。启动即打印 `CODE_VERSION` / 显存预算 / 精度 / 运行时梯度检查点 / rollout eval / `seed` |
| `mem_budget.py` | **开跑前必跑**：秒级估算显存峰值 + 判定能否放下 + 给安全 batch |
| `eval_grpo.py` | 评测。vLLM 优先（3 分钟/1319 题），支持 LoRA adapter 目录；**显式传 `repetition_penalty` / `top_p` / `eos`**；写子集指纹 |
| `compare_results.py` | 对照表 + 子集指纹校验 + **McNemar 配对检验** |
| `analyze_paired.py` | **配对 Δ 的 bootstrap 置信区间 + 交互检验**（支持 eval json 与评分 jsonl 两种输入）|
| `merge_adapter.py` | LoRA adapter 合并成完整模型（供 vLLM 加载），默认 CPU 合并不抢显存。**必须用 base 环境跑**（venv-vllm 没装 peft）|
| `filter_by_difficulty.py` | 难度筛选：vLLM 测每题通过率 → 评分文件 + 筛后数据集 + 一行 `SUMMARY` 汇总 |
| `prepare_data.py` | `--split train/test`：产出同格式数据集。test 供 `filter_by_difficulty.py` 用，**不打乱顺序**以便按题对齐 |
| `run_seeds.sh` / `eval_seeds.sh` | 换种子复现：训练 / 合并+评测+分析。可重入（已有产物则跳过）|
| `debug_completions.py` / `debug_train_rollout.py` | 单题原文 / 逐变量隔离（排查 rollout 问题的工具）|
| `docs/EXPERIMENT_LOG.md` | 本文件：完整实验记录（含被推翻的假设）|

> `results/*.json` 与 `outputs/` 不入库（见 `.gitignore`），按 README「快速开始」重跑即可生成。
